# 状态与工作树：实现记录

SQLite WAL 和 `BEGIN IMMEDIATE` 串行化共享任务写入；团队配置另用文件锁、revision CAS 和原子替换，旧实例保存时拒绝覆盖新数据；旧 JSON 只读导入并保留。运行记录使用 revision CAS，幂等键复用不同规格时拒绝；持久容量限制包括待启动、运行、空闲等待和取消请求，跨进程争用同一事务。TaskManager 可持久记录完成结果、停止原因、心跳和未知进程状态；重启遇到未终结运行标记为未知且不自动派发。取消协程不证明外部进程退出。应用入口必须指定持久库路径与稳定 session scope；AgentTool 共享持久 spawn 配额，前台、后台、工作树和进程内队友统一检查深度、总量和并发。终端队友因无法验证权限和配额传递而拒绝启动。TokenBudget 实现持久分项计数、scope 不变上限和每次请求前预检；主循环、压缩和辅助调用已接线；整体预算行为需独立集成回归。并发或单个在途请求可越过阈值，overrun 会单独记录。

邮箱领取后只由同一 owner 确认或释放；过期领取不自动重放，因为工具可能已有外部效果。旧 consume 为非破坏式读取；调用者必须迁移至 claim/ack，读取本身不等于持久交付。旧邮箱文件保留并只读导入。

Git 公共目录 flock 协调本实现的多个进程，并不约束其它 Git 客户端。同名分支不重置，自动清理关闭。清理前要求进程清单已封存、持久所有者记录、同主机、租约过期且所有已登记 PID 不存在；默认清单未封存，清理被阻止；无法查证就保留。记录带进程启动身份，PID 存在或权限不明均不视为退出。重启 reconcile 检查注册路径、分支和基线。清理计划保存 manifest 哈希及 HEAD；应用时再检查所有者、基线、分支和包含 ignored/untracked 的工作树状态，Git 失败保留，分支不隐式删除。

所有者退出并不能单独证明其曾启动的外部子进程退出，也不能证明其它未登记进程没有打开目录；当前进程归属不是 OS 沙箱。集成前必须识别和登记需要追踪的外部进程，无法证明时保留目录。调用方不能将清理 API 当成已验证的全部进程退出证据。

定向结果详见 state-focused.log、state-focused-junit.xml 和 state-manifest.json。旧测试中两项邮箱断言原要求破坏式消费/清空，已改为验证显式 ACK 与未确认消息保留，理由是避免处理前丢失。对照冻结基线后已迁移旧 mock 路径、提示词接口、工作树 fixture 和受控清理断言；当前 tests/test_teams.py 与 tests/test_worktree.py 合计 103 通过，迁移原因逐项见 state-test-migration.md。更大范围最终需由主 agent 在集成完成后重跑。

并发测试最初出现一次 `sqlite3.OperationalError: database is locked`，触发点是多个进程首次设置 WAL；随后加入有界重试，并在 10 次独立四进程启动中通过。该结果是竞争条件回归，不代表所有崩溃和存储故障均已覆盖。
