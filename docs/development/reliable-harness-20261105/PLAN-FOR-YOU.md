# GCode 本轮交付说明

本轮把 GCode 的重点放在执行可靠性：父子任务共用一套循环，目录和权限按任务隔离，任务/消息/预算持久化，未知写入保留回执并停止，Worktree 保守清理，大输出保存完整证据。可选 CU 已接到本机已安装的原生桥，公开仓库只含独立适配代码。

目前可使用 TUI 或 headless 入口，默认不启用 CU。需要本机 CU 时使用自己的私有配置，先只读验证身份和 scope，再按已授权范围开放写入。没有对应桥和二进制的机器仍可使用普通编程工具。两次界面切换已恢复原状，一次真实模型只读定位成功；尚不足以证明跨应用成功率、相对 pi 加速或文本输入可靠性。

测试记录保存了原基线失败、修复中失败与最终回归，技术理由见 [root-decisions.md](root-decisions.md)。压缩会保存原文但摘要仍可能语义遗漏；用户正文过长时拒绝压缩。token 预算无法硬性中断已在途请求；应用权限也不是操作系统沙箱。终端团队后端暂不能通过缺失的授权传递路径启动。

迁移前备份原会话、SQLite/WAL、工件和工作树，关闭旧进程后切换版本；效果未知的动作先核对，不能靠重启或换状态目录重新执行。回退时保留新版本的审计证据，让旧版本读取迁移前副本，避免旧程序覆盖新状态。细节和验收见 [执行版](PLAN-FOR-AI.md)。

最终全量回归794项通过；wheel已在全新虚拟环境安装并检查CLI与六个sidecar文件。证据索引见 [DELIVERY.json](DELIVERY.json)。

平台范围：本轮实际验证是macOS Apple Silicon。加固实现使用POSIX文件锁/进程组，Linux需独立验收，Windows需平台适配；不沿用旧README的跨平台支持描述作为本轮证据。
